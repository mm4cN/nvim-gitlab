==============================================================================
REQUIREMENTS                                        *gitlab-requirements*

- Neovim 0.12+
- git
- glab (required)
- yq with YAML-to-JSON single- and multi-document support (required for CI)
- nui.nvim (required)
- telescope.nvim (optional, for Telescope picker backend)

GITLAB_TOKEN is optional when glab is already authenticated. It is required
only by :GitlabAuth. CI discovery probes generic YAML-to-JSON single- and
multi-document capabilities instead of relying on a yq vendor or version.

Authentication is performed through the glab CLI.

The plugin can authenticate glab for the GitLab instance associated
with the current repository remote.

Supported remotes:

    git@gitlab.com:group/project.git
    https://gitlab.com/group/project.git
    https://gitlab.example.com/group/project.git

==============================================================================
CONFIGURATION                                      *gitlab-configuration*

Default configuration:
>
    require("gitlab").setup({
        glab_binary = "glab",
        gitlab_token_env = "GITLAB_TOKEN",
        ci_file = ".gitlab-ci.yml",
        picker = "vim_ui",
        scratch_height = 15,
        artifacts_dir = "gitlab-artifacts",
        extract_artifacts = true,
    })
<
    glab_binary        glab executable name or path.
    gitlab_token_env   Environment variable containing a GitLab token.
    ci_file            CI file validated by :GitlabCiValidate.
    picker             "vim_ui" or "telescope". Unknown or unavailable
                       backends fall back to vim.ui.
    scratch_height     Height of scratch-buffer views.
    artifacts_dir      Artifact download directory, relative to cwd.
    extract_artifacts  Extract downloaded archives when true.

COMMANDS                                              *gitlab-commands*

Health:

    :GitlabAuth
        Authenticate glab for the current repository host.

    :GitlabHealth
        Display plugin health information.

CI:

    :GitlabCiValidate
        Validate the configured CI file.

Pipelines:

    :GitlabPipelineRun
        Open the pipeline runner. Pre-fills the current
        repository project and branch. Supports editing the target project
        and ref, and running a pipeline for any accessible GitLab project.

        Runner fields:

            Project         GitLab project in namespace/project format.
            Ref / Branch    Branch or ref to run the pipeline on.
            Inputs          Discovered spec:inputs fields (experimental).
            Variables       User-defined pipeline variables (KEY=VALUE).

        Runner keybindings:

            Tab / S-Tab     Move to next / previous field.
            j / k           Move through an option field.
            Down / Up       Move through an option field.
            <C-p>           Pick an accessible project (all fields).
            <C-r>           Pick a branch from the selected project
                            (all fields).
            a               Add a pipeline variable field (normal mode).
            d               Remove the focused user-added variable (normal
                            mode). Discovered variables cannot be removed.
            <C-s>           Run the pipeline (all fields).
            <CR>            Commit or interact with the focused field.
            q / <Esc>       Close the runner.

        Pipeline variables are independent from spec:inputs. Variables are
        passed to glab as --variables KEY:VALUE. Discovery refreshes
        automatically after the project or ref changes.

        The runner is split into two rounded panes: a fixed-height scrollable
        form on the left and a fixed, non-focusable keybinding legend on the
        right. Tab and S-Tab automatically scroll an off-screen destination
        into view. A proportional scrollbar is shown when the form exceeds
        the viewport. The outer runner does not grow with discovered or
        manually added fields.

        Project changes resolve the canonical path_with_namespace and switch
        Ref to the project's default branch. Manually added variables survive
        project/ref discovery transitions. Project and Ref picker cancellation
        restores coherent visible values and focus.

        Fields with configured options are selection menus; other fields
        remain editable inputs. Multiline option labels are normalized for
        display, while the original selected value is submitted unchanged.

        Automatic YAML discovery is EXPERIMENTAL and requires a compatible yq
        YAML-to-JSON transcoder. spec:inputs are read from the root
        .gitlab-ci.yml; legacy described variables are read from GitLab's
        include-expanded merged YAML. GitLab-specific discovery is performed
        in Lua. Successful transcoding strategies are cached for the current
        Neovim session.

    :GitlabPipelineStatus
        Show the latest pipeline for the current branch.

    :GitlabPipelineList
        Select a pipeline and open its details view. Press <C-p> in the
        pipeline picker to select another accessible project. The current
        project is displayed in the picker prompt, and up to 100 recent
        pipelines are fetched for local filtering. The selected project remains
        active through pipeline/job details, logs, artifacts, refresh,
        retry/play, and pipeline rerun actions.

Jobs:

    :GitlabJobList
        Select a job and open its details view.

PICKERS                                                *gitlab-pickers*

The plugin provides a picker abstraction that supports multiple backends.

vim.ui Backend (default):

    Uses Neovim's built-in vim.ui.select() for basic selection.

Telescope Backend:

    Enhanced picker with additional features:
    - Preview pane showing available actions
    - Custom keybindings for quick actions

    Enable Telescope backend:
>
        require("gitlab").setup({
            picker = "telescope",
        })
<
Telescope Picker Actions:

    Pipeline Picker:
        <CR>    View pipeline details
        <C-r>   Re-run pipeline directly
        <C-p>   Select another accessible project

    Job Picker:
        <CR>    Select job for action

    The preview pane displays available actions, keybindings, and details
    for the selected pipeline or job.

==============================================================================
PIPELINES                                            *gitlab-pipelines*

Pipeline views provide interactive navigation and actions.

Pipeline Status:

    q       Close view

Pipeline Details:

    r       Refresh pipeline details
    <CR>    Open selected job details
    L       Open selected job logs
    A       Download selected job artifacts
    R       Re-run pipeline
    b       Navigate back
    q       Close view

Displayed information:

- Pipeline status
- Branch / ref
- Commit SHA
- Creation time
- Update time
- Pipeline jobs

==============================================================================
JOBS                                                      *gitlab-jobs*

Job views expose pipeline job information and actions.

Job Details:

    r       Refresh job details
    L       Open job logs
    A       Download job artifacts
    R       Retry job
    P       Play manual job (if manual)
    b       Navigate back
    q       Close view

Displayed information:

- Job status
- Stage
- Ref
- Duration
- Pipeline information
- Commit information

Manual Jobs:

Manual jobs require explicit triggering.

In job list and job details views, press P to play a manual job.

In the job list, press P to attempt to play the selected job. The plugin
verifies that the job has manual status before sending the request.

In job details, the P action is shown only for manual jobs.

==============================================================================
ARTIFACTS                                            *gitlab-artifacts*

Artifacts can be downloaded directly from job views.

Downloaded artifact archives are stored in:

    {artifacts_dir}/job-{job_id}-artifacts.zip

If extraction is enabled:

    extract_artifacts = true

archives are automatically unpacked after download to:

    {artifacts_dir}/job-{job_id}

Artifact views provide:

    b       Navigate back
    q       Close view

==============================================================================
INTERACTIVE VIEWS                                      *gitlab-views*

Views are displayed in a reusable scratch window.

Navigation hierarchy:

    Pipeline List picker
        |
        +-- Pipeline Details
                |
                +-- Job Details
                |
                +-- Job Logs
                |
                +-- Artifact Download

The 'b' key returns to the previous view.

Most interactive views display action hints at the top of the buffer.

LUA API                                               *gitlab-lua-api*

Supported functions:

    require("gitlab").setup(opts)
        Configure and initialize the plugin.

    require("gitlab.statusline").get()
        Return cached statusline data without blocking.

    require("gitlab.statusline").clear_cache()
        Clear statusline context and pipeline caches.

Other gitlab.* modules are internal implementation details and may change.

==============================================================================
STATUSLINE                                          *gitlab-statusline*

A lightweight API exposes current-branch pipeline status for use in any
statusline plugin or native Neovim statusline.

Public function:

    require("gitlab.statusline").get()

Returns a table with the following fields when a pipeline is found:

    status        Raw pipeline status string from GitLab.
    icon          Single Unicode character from the icon map.
    text          Ready-to-use string: icon .. " " .. status.
    pipeline_id   Numeric pipeline ID.

Returns an empty table ({}) when there is no repository, no pipeline for
the current branch, or when any error occurs. Failures are silent.

Recognised status values and their icons:

    success   ✓
    failed    ✗
    running   ●
    pending   ○
    canceled  ⊘
    skipped   ↷
    manual    ◆
    created   ◇

Results are cached for 60 seconds per project+branch pair. The cache is
keyed by project and ref, so switching branches fetches a fresh result.

Native Neovim statusline example:
>
    vim.o.statusline = "%{%v:lua.require('gitlab.statusline').get().text or ''%}"
<
lualine integration example:
>
    require("lualine").setup({
      sections = {
        lualine_x = {
          function()
            return require("gitlab.statusline").get().text or ""
          end,
        },
      },
    })
<
==============================================================================
HEALTH CHECKS                                         *gitlab-health*

Standard Neovim health checks:

    :checkhealth gitlab

Plugin health command:

    :GitlabHealth

Authentication command:

    :GitlabAuth

Health checks include:

- git availability
- glab availability
- required yq single- and multi-document YAML-to-JSON capabilities
- required nui.nvim availability
- configured Telescope picker availability and vim.ui fallback
- optional token status for :GitlabAuth
- repository root detection
- remote URL detection
- GitLab host detection
- glab authentication status
- GitLab API access validation
