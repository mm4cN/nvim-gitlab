==============================================================================
REQUIREMENTS                                        *gitlab-requirements*

- Neovim 0.12+
- git
- glab
- GitLab Personal Access Token
- telescope.nvim (optional, for Telescope picker backend)

Authentication is performed through the glab CLI.

The plugin can authenticate glab for the GitLab instance associated
with the current repository remote.

Supported remotes:

    git@gitlab.com:group/project.git
    https://gitlab.com/group/project.git
    https://gitlab.example.com/group/project.git

==============================================================================
COMMANDS                                              *gitlab-commands*

Health:

    :GitlabAuth
        Authenticate glab for the current repository host.

    :GitlabHealth
        Display plugin health information.

CI:

    :GitlabCiValidate
        Validate the configured CI file.

Pipelines:

    :GitlabPipelineRun
        Run a new pipeline for the current branch.

    :GitlabPipelineList
        List recent project pipelines.

    :GitlabPipelineStatus
        Show the latest pipeline for the current branch.

    :GitlabPipelineDetails
    :GitlabPipelineDetails {pipeline_id}

Jobs:

    :GitlabJobList
        List jobs from the latest pipeline.

    :GitlabJobLogs
    :GitlabJobLogs {job_id}

    :GitlabJobRetry
    :GitlabJobRetry {job_id}

    :GitlabJobDetails {job_id}

    :GitlabJobArtifacts {job_id}

PICKERS                                                *gitlab-pickers*

The plugin provides a picker abstraction that supports multiple backends.

vim.ui Backend (default):

    Uses Neovim's built-in vim.ui.select() for basic selection.

Telescope Backend:

    Enhanced picker with additional features:
    - Preview pane showing available actions
    - Custom keybindings for quick actions

    Enable Telescope backend:
>
        require("gitlab").setup({
            picker = "telescope",
        })
<
Telescope Picker Actions:

    Pipeline Picker:
        <CR>    View pipeline details
        <C-r>   Re-run pipeline directly

    Job Picker:
        <CR>    Select job for action

    The preview pane displays available actions, keybindings, and details
    for the selected pipeline or job.

==============================================================================
PIPELINES                                            *gitlab-pipelines*

Pipeline views provide interactive navigation and actions.

Pipeline List:

    r       Refresh pipeline list
    <CR>    Open pipeline details
    R       Re-run pipeline
    q       Close view

Pipeline Status:

    q       Close view

Pipeline Details:

    r       Refresh pipeline details
    <CR>    Open selected job details
    L       Open selected job logs
    A       Download selected job artifacts
    R       Re-run pipeline
    b       Navigate back
    q       Close view

Displayed information:

- Pipeline status
- Branch / ref
- Commit SHA
- Creation time
- Update time
- Pipeline jobs

==============================================================================
JOBS                                                      *gitlab-jobs*

Job views expose pipeline job information and actions.

Job List:

    r       Refresh job list
    <CR>    Open job details
    L       Open job logs
    A       Download job artifacts
    R       Retry job
    P       Play manual job
    b       Navigate back
    q       Close view

Job Details:

    r       Refresh job details
    A       Download job artifacts
    R       Retry job
    P       Play manual job (if manual)
    b       Navigate back
    q       Close view

Displayed information:

- Job status
- Stage
- Ref
- Duration
- Pipeline information
- Commit information

Manual Jobs:

Manual jobs require explicit triggering.

In job list and job details views, press P to play a manual job.

In the job list, press P to attempt to play the selected job. The plugin
verifies that the job has manual status before sending the request.

In job details, the P action is shown only for manual jobs.

==============================================================================
ARTIFACTS                                            *gitlab-artifacts*

Artifacts can be downloaded directly from job views.

Downloaded artifacts are stored in:

    {artifacts_dir}/{job_id}

If extraction is enabled:

    extract_artifacts = true

archives are automatically unpacked after download.

Artifact views provide:

    b       Navigate back
    q       Close view

==============================================================================
INTERACTIVE VIEWS                                      *gitlab-views*

Views are displayed in a reusable scratch window.

Navigation hierarchy:

    Pipeline List
        |
        +-- Pipeline Details
                |
                +-- Job Details
                |
                +-- Job Logs
                |
                +-- Artifact Download

The 'b' key returns to the previous view.

Most interactive views display action hints at the top of the buffer.

==============================================================================
HEALTH CHECKS                                         *gitlab-health*

Standard Neovim health checks:

    :checkhealth gitlab

Plugin health command:

    :GitlabHealth

Authentication command:

    :GitlabAuth

Health checks include:

- git availability
- glab availability
- repository root detection
- remote URL detection
- GitLab host detection
- glab authentication status
- GitLab API access validation
